# Feature: Technical tab - call and recording settings

**From build-plan:** feature 23b

**Status:** complete

## Goal

Add the five new per-assistant settings the user asked for to the Technical tab: max call
duration, max silence timeout, a recording toggle, auto-delete-on-declined-consent, and an
ambient-sound preset (office/conference room) with a volume level. All five are
**configuration-only** - saved and shown in the UI, but not yet enforced against a real call,
since real call handling (build-plan items 24-28: telephony provider, number provisioning,
inbound handling, call records, recording) does not exist yet. This was confirmed explicitly with
the user before scoping this sub-feature.

## Design reference

None. Reuses the existing dark-theme form-input styling already established on the Technical tab
by 23a.

## Architecture decisions (read before building)

- **These five fields live on `AssistantVersion`, the same immutable snapshot everything else on
  the Technical tab already lives on** - not a new table.
- **`max_call_duration_seconds` and `max_silence_timeout_seconds` are nullable integers, no
  default.** Unset (`null`) means "no limit configured yet." Bounds are sanity checks only
  (30s-3600s for call duration, 5s-300s for silence timeout).
- **"Max silence timeout" is the caller-silence-during-a-call meaning**, confirmed with the user -
  not ring/answer wait time and not turn detection's own `FALLBACK_TIMEOUT_SECONDS` (a different,
  already-shipped, per-turn concept).
- **`record_calls` and `auto_delete_on_declined_consent` are `NOT NULL` booleans defaulting to
  `false`.** CLAUDE.md section 20 says recording is "off by default." The migration backfills
  existing rows with `false` via `server_default`.
- **`ambient_sound` stays the same free-text `String(255)` column - no backend enum.** The
  frontend constrains input to a `<select>` with exactly two real presets (`office`,
  `conference_room`) plus "None." A companion `ambient_sound_volume: float | None` (0.0-1.0) is
  the one genuinely new column here.
- **Two build steps: backend then frontend.**

## In scope

- Five new `AssistantVersion` columns, threaded through model/schema/service/repository/route.
- `apps/web/lib/assistants.ts` type updates.
- Technical tab UI: two number inputs, two checkboxes, ambient sound preset `<select>` + volume.

## Out of scope

- Any actual enforcement (call-duration cutoff, silence detection, real recording, real deletion).
- A consent-announcement flow or UI.
- Any change to `ambient_sound`'s column type or a backend enum/check constraint.

## Notes for the AI

- **The autogenerated Alembic migration omitted `server_default` on the two new `NOT NULL`
  boolean columns** - always check autogenerated migrations for this when adding a `NOT NULL`
  column with a Python-level `default=` to a table that may already have rows; the ORM default
  only applies to new inserts, not existing rows, so the migration itself needs
  `server_default=sa.false()` (or the appropriate literal) to backfill correctly.
- Alembic must run inside the `api` container (`docker compose exec api alembic ...`), not from
  the host - `DATABASE_URL` uses the Compose service name `postgres`, which only resolves inside
  the Docker network.
- The `norma-web` container's dev server needed a `--force-recreate` restart before manual
  verification would reflect the new code, and its first request after a restart can take
  20-40+ seconds while Turbopack compiles - worth a generous `curl` timeout rather than assuming
  a fast health check.
